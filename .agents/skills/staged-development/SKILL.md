# 分階段開發流程

把非瑣碎工作拆成「提案 → 實作 → 歸檔」，未取得使用者核准不得跨越提案與實作的邊界。

## 1. 提案

1. 先讀取專案規範、相關原始碼、測試與現有文件。
2. 建立一份提案，至少包含：問題、範圍、非目標、方案、受影響檔案、驗證方式與風險。
3. 把仍需使用者決定的事項列為明確問題，不用實作掩蓋歧義。
4. 提案完成後停止，等待使用者核准或修訂。

## 2. 實作

1. 只實作已核准的提案；若發現需要擴大範圍，先更新提案並重新取得核准。
2. 優先建立可重現失敗或描述新行為的測試，再做最小變更使其通過。
3. 執行提案列出的驗證並記錄結果；不要以略過檢查或寫死值處理失敗。
4. 報告已完成項目、偏離提案之處與仍存在的阻礙。

## 3. 歸檔

1. 只有在實作與必要驗證完成後才歸檔。
2. 保存最終決策、實際變更、驗證證據、已知限制及後續工作。
3. 提案若被拒絕，也要保留拒絕原因與已證明無效的方案，避免未來重試。
